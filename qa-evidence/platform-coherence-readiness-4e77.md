# Platform coherence browser regressions on source 4e77d129

The published QA run [38083486841](https://github.com/yarinn12/sogrim-hashbon/actions/runs/38083486841) used exact application source `4e77d12932f281377a2f3d8d2b0755d380ff39a5`. Its first desktop Firefox attempt timed out in the shared `platform-coherence-regression.spec.mjs` `beforeEach` while `page.goto('/')` waited for document `load`; the retry passed. The full cross-platform job still failed under `failOnFlakyTests` (170 passed, 4 skipped, 1 flaky). Trace [artifact 11681378889](https://github.com/yarinn12/sogrim-hashbon/actions/runs/38083486841/artifacts/11681378889) records 152 completed requests (151 HTTP 200, one HTTP 206), a rendered home screen, and the pending `load` wait. It does **not** identify the delayed resource. The extracted `trace.zip` SHA-256 is `E64E72081EB72E90ECA95DEB36B7F24DFA2F3B16651F2629CBBD8D2BCB0CB4B0`.

The same run's Android browser profile timed out clicking the first generic `settle` control after saving and expanding an expense note. The trace resolves that control to the workspace summary tab, then repeatedly records it as hidden; the page snapshot shows the separate visible personal balance summary card. The retry passed, but `failOnFlakyTests` failed the mobile job (278 passed, 10 skipped, 1 flaky). Trace [artifact 11681364283](https://github.com/yarinn12/sogrim-hashbon/actions/runs/38083486841/artifacts/11681364283) has extracted `trace.zip` SHA-256 `AED9E32ECD92889BCA7EC47600FC06254D641DF51CFED84B6F0F50B78A9427EF`.

The shared platform coherence fixture now waits for DOM content, the visible app home, and the actual local Hebrew Rubik face. It requests that face directly with `document.fonts.load` because a held image can keep `document.fonts.ready` pending in WebKit. The 32px roster's second navigation uses the same readiness boundary. The note journey selects the visible personal balance card by its own class and event identity and checks that its center receives a tap before clicking. Route, screen, font, geometry, persistence, and behavior assertions remain.

Regression evidence:

- A new held-image test in the affected fixture failed before the navigation change: its `beforeEach` reached the 15-second controlled reproduction deadline at `page.goto('/', waitUntil: 'load')`. After the change, all nine browser/mobile profiles passed with the image still held and `document.readyState === 'interactive'`. The production suite's 90-second test timeout and `failOnFlakyTests` were not changed.
- The published Android trace is the red example for the existing long-note journey's generic summary click. With the specific visible card and tap check, the focused Android journey passed locally. The prior CI failure was intermittent, so this is regression coverage of the route and tap target, not proof that the timing issue cannot recur.
- On the exact source plus the test fix, `npm test` passed 3394/3394. The focused Firefox readiness and roster checks passed 6/6. The typography spillover checks at 32px and AX size passed 2/2 on the iPhone large-text profile. The cross-platform affected file passed 24/24 and the mobile affected file passed 30/30 locally. These are synthetic local browser tests; they are not real-device or production latency measurements.

The CI artifacts are retained by the workflow for 14 days. Local extracted traces are in the ignored `ci-traces/` directory of this QA worktree; this note records their provenance and hashes without committing the large binaries.
