# QR אופציונלי של Bit בפרופיל — ענף מועמד

המימוש נמצא בענף `codex/bit-qr-profile-20261101`, מעותק נפרד שהתחיל ב־`97eee781a6a4c869540fcc113e9146e44fb6478c`. הוא אינו פרסום לאפליקציה הפעילה. לא הופעלה מיגרציה בייצור ולא שונו מספרי הבנייה בחנויות.

## תחום המימוש

בפרופיל של חשבון מחובר נוסף אזור „Bit — לא חובה”: בחירת תמונה, זיהוי מקומי, שמירה מפורשת, החלפה, הסרה ורענון. הוא אינו מופיע כתנאי בהרשמה או בהצטרפות לאירוע. שם, שם משתמש ותמונת פרופיל ממשיכים להשתמש במסלולים הקיימים.

`BIT_QR_PROFILE_ENABLED` כבוי כברירת מחדל. מפעילים אותו רק בסביבת בדיקה מבודדת לאחר התקנת המיגרציה ואימות ההרשאות. אין להפעיל את מתג ההפצה של האפליקציה כחלק מבדיקה זו.

התמונה מפוענחת במכשיר באמצעות Worker ומפענח jsQR 1.4.0 מקומיים. היא אינה עולה לשרת או נשמרת. השרת מקבל רק קישור אישי תחת `https://www.bitpay.co.il/app/me/` וגרסה צפויה. הלוגו המקורי של Bit הועתק מהאתר הרשמי, ללא שינוי צבעים או פרופורציות. רישיון המפענח מצורף ב־`assets/bit/vendor/`.

אין כאן אימות בעלות על חשבון Bit, חיבור לממשק של הספק, הפקת קישור לפי מספר טלפון, מילוי סכום אוטומטי או ביצוע תשלום. כפתורי התשלום והסימון הקיימים לא שונו בשלב הזה.

## נתונים והרשאות

הטבלה `private.user_bit_shortcuts` מחזיקה מזהה חשבון, קישור או `null`, גרסה מונוטונית ותאריך שרת. אין הרשאות טבלה ישירות ל־`anon` או ל־`authenticated`.

- `get_my_bit_shortcut()` קוראת את רשומת המתקשר המחובר בלבד.
- `set_my_bit_shortcut(p_bit_url, p_expected_revision)` קובעת את הבעלים מתוך `auth.uid()`. היא נועלת את הרשומה ודוחה גרסה ישנה. אין פרמטר לבחירת בעלים אחר.
- `get_transfer_bit_shortcut(p_snapshot_id, p_transfer_id)` הוכנה לחיבור עתידי למסך התשלום. היא קובעת את המקבל מתוך חוב פתוח וקנוני של המתקשר, מאמתת חברות פעילה וחסימות ומחזירה את קיצור המקבל. אין חיפוש ציבורי לפי מספר טלפון או מזהה משתמש חופשי.

הסרה נשמרת כ־`null` עם גרסה חדשה, כדי שטיוטה ישנה לא תחזיר קישור שהוסר. לאחר שגיאה או תשובת שמירה לא ודאית נדרש רענון מהשרת לפני ניסיון כתיבה נוסף. הצלחה מוצגת רק לאחר ACK תקין של החשבון, הקישור והגרסה הנכונים.

המסך רענן בכניסה לפרופיל ובפעולת „רענן את פרטי Bit”. אין טענה לסנכרון Push מיידי בזמן שהמסך עומד פתוח. כל שליפה של יעד תשלום היא קריאה טרייה, ללא מטמון קישורים ציבורי.

קישורים אינם נוספים ל־`user_profiles`, למסמכי אירוע, להתראות או ליומנים. מחיקת חשבון מנקה את הרשומה דרך מסלול מחיקת הנתונים הקיים ו־FK של Auth. הסרת הקיצור אינה מבטלת קישור Bit שהועתק מחוץ לאפליקציה.

## התקנה עתידית בסביבה מבודדת

המיגרציה: `supabase/migrations/20261101190000_optional_private_bit_profiles.sql`.

אימות הרשאות לקריאה בלבד: `supabase/verification/verify_20261101190000_optional_private_bit_profiles.sql`.

יש להריץ התקנה במסגרת עסקת מסד ובסביבת בדיקה מאושרת בלבד. כל הקוד נמצא גם בסכמה הקנונית, ובדיקות משוות את כל טקסט המיגרציה מול אותה סכמה. נבדקו התקנה חדשה, שדרוג סכמה קיימת והפעלה חוזרת.

לפני הפעלה בייצור נדרשים תנאי המסד, המקור האחיד, ארבע קבלות ה־CI וההפצה הקיימים. החזרה המיידית היא כיבוי הפיצ׳ר ושימוש בפרופיל ובחובות הרגילים. נקודת Git אינה גיבוי מסד.

## בדיקות ללא שירותים חיים

```text
node --test tests/bitProfile.test.mjs
node --test tests/bitProfileSync.integration.test.mjs
npm run qa:sync -- e2e-sync/bit-profile-cloud.spec.mjs
npm run qa:architecture
npm test
```

בדיקת הסנכרון מפעילה PostgreSQL אמיתי דרך PGlite, את הסכמה, המיגרציה וההרשאות האמיתיות של המועמד, ומעבירה את בקשות המתאם דרך HTTP מקומי. שכבת Auth/PostgREST המאוחסנת מדומה במכוון. אין קריאת `.env`, שימוש באסימונים אמיתיים או כתיבה לענן חי.

המבחן הקבוע ב־`e2e-sync/bit-profile-cloud.spec.mjs` משתמש ב־Chromium וב־WebKit עם אחסון וזהויות נפרדים, ועוד לקוח עצמאי לאותו חשבון. הוא מייבא שתי תמונות QR סינתטיות דרך הפרופיל האמיתי, שומר שני קישורים שונים, מאמת שיוך לחשבון, מסיר אחד ומוודא שההסרה מסתנכרנת בלי להשפיע על החשבון השני.

בדיקות הבקרה מכסות גם כתיבה ישנה, שתי כתיבות מתחרות, חסימות, חברות באירוע, איסור קריאת טבלה ישירה, קישור פסול, החלפת חשבון באמצע בורר Native או שמירה, שגיאת ACK ושמירת נתוני זהות וכספים ללא שינוי.

## גבולות האישור

בדיקות דפדפן ו־WebKit ב־Windows אינן בדיקת Native פיזית או אישור חזותי ל־iOS. נדרשת בדיקה בחבילת Android וב־iPhone מתאימים: גלריה והרשאות, חזרה מהרקע, פענוח צילום אמיתי וטעינת הנכסים הארוזים. חיבור כפתור התשלום לקיצור המקבל ולסכום האמיתי הוא שלב נפרד שעדיין לא הופעל.

בדיקת אריזת ה־Native משתמשת בתצורת QA סינתטית לא מקוונת. היא אינה APK/IPA להגשה או חבילה להפצה למשתמשים.
