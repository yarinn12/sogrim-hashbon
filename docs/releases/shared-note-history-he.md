# סנכרון פתקים באירועים ותיקים — PWA 455

## תרחיש ושורש התקלות

משתתף יוצר, עורך או מוחק פתק; השמירה עוברת למקור המשותף בשרת, משוכפלת לעותקים האישיים באותה טרנזקציה, ומשם מופיעה אצל המשתתפים האחרים.

נמצאו ושוחזרו שני כשלים נוספים:

- אחרי 500 מחיקות, הלקוח קיצץ היסטוריה בעוד מיזוג עם השרת החזיר יותר מ־500 רשומות. מגבלת האימות דחתה שמירה, וקיצוץ ההיסטוריה עלול היה לאפשר לעותק ישן להחזיר פתק שנמחק.
- מחיקה שהוכנה לפני עריכה ממכשיר אחר הסירה את הפתק לפי מדיניות המיזוג הקיימת, אבל חותמת הזמן שלה הייתה מוקדמת מדי ביחס לעריכה המאושרת. בדיקת ההרשאות בשרת דחתה אותה.

בדיקת שני חשבונות לפני החלת התיקון החזירה HTTP 400 בשמירת ההיסטוריה הארוכה. שש בדיקות רגרסיה חדשות נכשלו לפני תיקון קוד הלקוח.

## התיקון

- היסטוריית המחיקות נשמרת ללא קיצוץ שרירותי לפי מספר הרשומות. מגבלת 8 MiB למצב השמור במסד ומגבלת 100 פתקים פעילים נשארות בתוקף. מחיקת היסטוריה עתידית תחייב מנגנון תיאום מתאים, ולא חיתוך מערך.
- השרת משלים רשומות מחיקה מאושרות שהושמטו מבקשה של לקוח ישן. מזהי מחיקות קיימים נשארים בלתי משתנים.
- מחיקה ממתינה מותאמת לזמן העריכה המאושרת האחרונה, לפי מדיניות המחיקה הקיימת. זהות המבצע וההרשאות אינן משתנות.
- אימות ההיסטוריה משתמש במיפוי לפי מזהה במקום סריקות חוזרות של המערך כולו.
- המיגרציה `20260903223000_preserve_complete_note_history.sql` הוחלה אחרי בדיקת טרנזקציה שבוטלה. עדכון הלקוח מופץ ב־PWA 455; אין כאן חבילת חנות חדשה.

## ראיות אימות לפני הפצת הלקוח

- כל 1,753 בדיקות הקוד עברו, ללא כישלונות או בדיקות מדולגות.
- עשר בדיקות חדשות מכסות גבולות 499/500/501/1000 מחיקות, מחיקות במקביל, עותק ישן, מחיקה מול עריכה, שימור זהות המבצע והתאמת סכמת התקנה חדשה למיגרציה.
- בדיקת מסד: 501 רשומות מחיקה מתקבלות; רשומות כפולות, החייאת פתק, תאריך בלתי תקין, 101 פתקים פעילים ומחיקה המיוחסת למשתמש אחר נדחים.
- בדיקת שני חשבונות חיה עברה אחרי המיגרציה: יצירה, עריכה, מחיקה, שמירות חופפות, עותק אישי ישן, חזרה לחיבור, מחיקה כפולה, היסטוריה ארוכה והשלמת היסטוריה שקוצצה בלקוח ישן. העותקים האישיים התאימו למקור המשותף.
- זמני שמירה ושכפול שנמדדו בבדיקת השרת: יצירה 417.9ms, עריכה 373.2ms, מחיקה 369.2ms. אלה אינם זמני רינדור במכשיר המקבל.
- בדיקת ביצועי פונקציות המסד בלבד: 501 רשומות ב־40.1ms ו־5,001 רשומות ב־340.2ms. זו דגימה מבודדת, לא מבחן עומס או הבטחת זמן תגובה.
- חשבונות ונתוני הבדיקה הזמניים נוקו.

## פריסה וגבולות האימות

- יעד: production, בכתובת https://sogrim-hesbon-app.vercel.app, באמצעות חיבור Git הקיים.
- סוג האפליקציה: JavaScript modules עם שרת Node ו־Supabase.
- נוהל הפריסה מבוסס על מיומנות `vercel:deployments-cicd`: מיגרציה, אימות, ואז הפצת הלקוח ואימות התוכן הציבורי.
- גישת כלי Vercel לפרויקט וליומני זמן הריצה החזירה 403. משך הבנייה, סריקת שגיאות, Drains והגדרות ניטור אינם מאומתים; אין טענה שיומני השרת נקיים.
- אין בדיקה על iPhone פיזי ואין הבטחה לאפס השהיה או לסנכרון מקוון בזמן ניתוק. בדיקות דפדפן WebKit אינן תחליף מלא למכשיר אמיתי.
