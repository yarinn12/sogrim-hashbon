# גרסה 471 — שמירה חדשה אינה מאשרת פתק שעדיין לא סונכרן

- שוחזר כשל בשתי בדיקות לפני התיקון: שמירת פתק באירוע א׳ נכשלת זמנית; שמירה מוצלחת באירוע ב׳ הייתה יכולה למחוק את כל תור הסנכרון, אף שפתק א׳ טרם הגיע לעותק המשותף. גם אחרי התאוששות השרת, השמירה הבאה הייתה מדלגת על פתק א׳.
- כל שמירה כוללת כעת גם את יעדי הסנכרון שעדיין ממתינים מהשמירות הקודמות. הצלחה של אירוע אחר אינה מספיקה כדי למחוק את העבודה שלא נמסרה.
- הכיסוי נשמר גם בשמירות חופפות ובשמירה אישית שאינה משנה אירוע. אחרי הפעלה מחדש, תור קיים בלי מידע על ההפרש המקורי עובר התאמה מלאה, כפי שנעשה כבר במסלול ההתאוששות.
- כל עוד ההפרש הממתין ידוע, אירוע שלישי שלא השתנה אינו נשלח מחדש. לא שונו תדירות הרענון, תבנית התור בדיסק או תשתית הסנכרון.
- נוספו שש בדיקות קוד ושני תרחישים דרך מסכי האפליקציה בחמש תצורות דפדפן. הסיפור הנבדק: עורך הפתק → תור מקומי עמיד → בקשת השמירה המשותפת → אישור/כשל → שמירה באירוע אחר → הצגת מצב הסנכרון והתאוששות.
- אימות סופי: 2,160 בדיקות קוד ו־65 בדיקות דפדפן עברו, ללא כישלונות. ריצת הדפדפן המלאה ארכה 3.8 דקות.
- בבדיקות ההפעלה מחדש הופרדה הודעת רשת פנימית של WebKit בזמן החלפת המסמך משגיאת אפליקציה: ההודעה נשמרת בדוח הבדיקה, וכל שגיאת JavaScript אמיתית או כשל מחוץ לחלון ההחלפה עדיין מכשילים אותה. נוספו שלוש בדיקות להגבלה זו; לא הוחלשה הצגת שגיאות באפליקציה עצמה.
- כל בדיקות התנהגות הסנכרון נעשו עם נתונים ותגובות שרת מדומים. הן אינן מדידת שיהוי ברשת אמיתית ואינן בדיקת מכשירי iPhone/iPad פיזיים.
- אין שינוי במסד הנתונים, בהרשאות, בשירות בתשלום או בבינארי האפליקציה.
