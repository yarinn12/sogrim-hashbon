# תיקון התנגשות שעונים בעריכת פתקים — PWA 456

## הכשל והתיקון

שתי עריכות שונות של אותו פתק יכולות לקבל חותמת זמן זהה. מדיניות המיזוג הקיימת בוחרת ביניהן באופן קבוע לפי התוכן, אבל השרת דורש שעריכה ששונה מהגרסה המאושרת תקדם את חותמת הזמן. כתוצאה מכך, עריכה שנבחרה במיזוג נדחתה ב־403, וחסמה גם פתק נוסף שנשלח באותה שמירה.

בבדיקת פונקציות המסד התקבלה רשומה תקינה (`valid: true`) שהשמירה שלה אסורה (`permitted: false`). ארבע בדיקות רגרסיה חדשות שחזרו את הכשל לפני התיקון.

התיקון נמצא בגבול המיזוג מול המקור המאושר: אם העריכה שנבחרה שונה מהגרסה המאושרת אך בעלת אותו זמן, היא מקבלת זמן המשך של אלפית שנייה. בחירת התוכן, זהות היוצר וזהות העורך אינן משתנות. רענון ושמירה חוזרת של אותה גרסה אינם מקדמים את השעון שוב. ייצוגים שקולים של זמן ושל הצמדה כבויה אינם הופכים לעריכה חדשה.

המיזוג בין עותקים מקומיים נשאר ללא שינוי. אין שינוי בהרשאות השרת או מיגרציית מסד חדשה. זו אינה מערכת למיזוג שני טקסטים בתוך אותו פתק: מדיניות בחירת הגרסה הקיימת נשארה בתוקף.

## בדיקות

- כל 1,763 בדיקות הקוד עברו, ללא כישלונות או בדיקות מדולגות.
- עשר בדיקות רגרסיה חדשות: התנגשות שעונים, פתק נוסף באותה שמירה, רענון, תשובה מאושרת, ניסיון חוזר לאחר התנגשות, גרסה מאושרת שזוכה, ייצוגי זמן שקולים, הצמדה כבויה, סדר הפתקים ומיזוג בין עותקים מקומיים.
- בדיקת שני חשבונות מבודדים מול השרת שחזרה 403 עם הבקשה הישנה, ואימתה שהדחייה לא שינתה נתונים. אותה פעולה עברה עם התיקון; הפתק הנוסף נשמר והעותקים האישיים התאימו למקור המשותף.
- הבדיקה החיה כיסתה גם יצירה, עריכה, מחיקה, חזרה מחוסר חיבור, מחיקות כפולות, היסטוריה ארוכה, שמירות חופפות ועותק אישי ישן. חשבונות ונתוני הבדיקה הזמניים נוקו.

## פריסה ומגבלות

- יעד: production, https://sogrim-hesbon-app.vercel.app, דרך חיבור Git הקיים.
- סוג האפליקציה: JavaScript modules, שרת Node ו־Supabase.
- גרסת הלקוח: PWA 456; לא נבנתה חבילת חנות חדשה.
- נוהל העבודה: `vercel:deployments-cicd`, עם בדיקות לפני הפצה ואימות תוכן האתר לאחריה.
- גישת יומני Vercel החזירה `Not authorized`. משך הבנייה, סריקת שגיאות זמן ריצה, Drains והגדרות ניטור אינם מאומתים; אין טענה שהיומנים נקיים.
- בדיקת WebKit אינה בדיקה על iPhone פיזי. אין הבטחה לאפס השהיה, לפעולה מקוונת בזמן ניתוק או לכך שלא יימצאו תקלות נוספות.
