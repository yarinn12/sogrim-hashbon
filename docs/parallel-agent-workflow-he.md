# עבודה מקבילית עם סוכנים

## מטרה

לקדם כמה תחומים במקביל בלי ליצור תיקונים סותרים, רגרסיות או שינויי עיצוב שלא אושרו. מנהל העבודה מרכז את סדר העדיפויות, מאחד את הממצאים ומאשר את האינטגרציה.

## תחומי אחריות קבועים

1. **QA מובייל** - מסעות משתמש מלאים ב-Android וב-iOS, ניווט, חזרה, דיאלוגים, טעינה, טקסט מוגדל וקריסות.
2. **UI/UX ונגישות** - אחידות מול מסך הבית המאושר, צפיפות, היררכיה, אייקונים, ניגודיות, אזורי לחיצה וגלישות.
3. **זהות וסנכרון** - מעבר בין חשבונות, בידוד מידע, חברים, שמות אונליין/אופליין, הזמנות, QR והתראות.
4. **חנויות ושחרור** - Google Play, App Store, פרטיות, מחיקת חשבון, פרסומות, הרשאות, גרסאות ונכסי חנות.
5. **ביצועים ועמידות** - זמן עלייה, רינדורים, זיכרון, עומס נתונים, תחרות בין עדכונים, retries ותצפיות מערכת.

## כללי עבודה

- סריקה מתחילה בממצאים והוכחות בלבד: חומרה, דרך שחזור, קובץ/שורה והבדיקה החסרה.
- שינוי בעיצוב מאושר דורש אישור מפורש לפני עריכה.
- תיקונים רצים במקביל רק כאשר לכל סוכן יש קבוצת קבצים נפרדת.
- קובץ משותף כמו `src/app.mjs`, `styles.css` או קובץ תצורה מרכזי מקבל עורך יחיד בכל סבב.
- אין לשנות לוגיקת חישוב, זהות או הרשאות כחלק מתיקון חזותי.
- כל תיקון כולל בדיקה ממוקדת. שינוי רוחבי עובר גם את שער הגרסה המלא.

## שער אינטגרציה

לפני בנייה או העלאה:

1. סקירת השינויים ובדיקת התנגשויות.
2. בדיקות ממוקדות לכל תחום שנגעו בו.
3. `npm run qa:coverage`.
4. `npm run qa:mobile` כאשר נגעו ב-UI או בניווט.
5. בדיקות live לזהות, חברים, התראות או סנכרון כאשר נגעו בענן.
6. `npm run qa:store` ו-`npm run native:prepare` לפני גרסת חנות.
7. בדיקה ידנית קצרה באמולטור Android לפני העלאה.

## סדר עדיפויות

1. קריסה, אובדן מידע, ערבוב משתמשים או חישוב שגוי.
2. פעולה מרכזית שלא עובדת: כניסה, הזמנה, הוצאה, סיכום או תשלום.
3. ניווט, עומס, נגישות ואלמנטים שמסתירים תוכן.
4. עקביות חזותית וליטושים.
5. פיצ'רים עתידיים ומיתוג מחדש.
