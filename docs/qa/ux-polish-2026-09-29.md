# Participant creation and keyboard-navigation polish — 2026-09-29

This pass preserves the existing Hebrew/RTL design and improves feedback and completion of event creation. Production group records were not changed.

## Findings and fixes

- Adding a manual participant cleared the input without showing the result. The editor now reuses the existing selected-participant roster, including its count and removal confirmation.
- **Save and return** previously left a typed name out of the event. It now commits that name through the same normalization, validation and duplicate-resolution path as **Add**, and stays on the editor for invalid input. An empty field returns without adding anyone.
- The single save button inherited a two-column layout on narrow screens. Only the two-action parent footer now uses that layout; the editor's save button fills its available width.
- The Hebrew skip-link label had a typo. Its fragment URL could also reload a URL containing a query because of the document's base URL, losing an unfinished event. Activation now focuses the existing main content without navigating.
- A delayed event-type autofocus callback could steal a later keyboard selection. It now checks the active draft, screen and focus before running. The skip link also remains fully inside the RTL viewport with enlarged text.

No financial calculation, participant-merging policy, synchronization protocol, account permissions or existing event data is changed.

## Permanent behavioral coverage

`e2e/manual-participant-feedback.spec.mjs` runs under all five existing mobile profiles in the normal QA workflow:

1. Immediate roster feedback, repeated addition, deduplication, confirmed removal, re-addition, and the actual saved event roster after reload.
2. Saving a pending name, restoring focus to the entry action, returning with an empty field, and persisted membership after reload.
3. Rejecting an invisible name in place, correcting it, and persisted membership after reload.
4. Holding and releasing a delayed autofocus frame, retaining keyboard focus, displaying the complete skip link, activating it without reload, and preserving an unfinished event name and URL.
5. Full-width save action at 390px, six added names, access to the last row, confirmed removal and successful return.

The tests seed storage only once, so reload checks read the application's saved state rather than reconstructing the expected result. They use local synthetic accounts. Mobile browser profiles do not constitute physical-device testing.

## Failure-before evidence

- All four initial behavioral tests failed against the unchanged application: missing roster, lost pending name, invalid-name navigation, and the incorrect skip-link label.
- After correcting the label, the skip-link test independently reproduced the reload and loss of focus.
- The narrow footer test measured **117.56px** of unused action width before the CSS correction.
- A controlled delayed-frame test failed by moving focus away from the skip link before the autofocus guard was added. Its assertion also requires the complete link to be in the viewport, rather than accepting a partially clipped link.

Logs and before/after screenshots are retained in the task's `outputs` directory. An initial combined mobile run stalled in the existing WebKit landscape-roster case and was interrupted; it is not counted as a successful run. The focused final suites are run independently.
