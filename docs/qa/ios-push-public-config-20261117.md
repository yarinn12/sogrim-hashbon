# אימות זהות התצורה הציבורית של Firebase לאייפון

הכלי הוא הכנה מקומית ל־Push ב־iOS. הוא אינו מפעיל תוסף, משנה תצורה,
יוצר מפתח או מאשר מסירה. בשלב זה הוא אינו מחובר למסלול הבנייה.

הקלט הוא קובץ JSON מצומצם של ארבעה שדות ציבוריים מהתצורה המקורית
של יישום iOS ב־Firebase: PROJECT_ID, GCM_SENDER_ID, BUNDLE_ID ו־GOOGLE_APP_ID.
אין להמציא את מזהה יישום האייפון או לגזור אותו מ־OAuth או מתצורת Android.
זה אינו parser של GoogleService-Info.plist; כשקובץ ה־plist המאומת יהיה זמין,
יש להפיק ממנו רק את ארבעת השדות לכלי זה ולשמור את המקור הנדרש לבנייה בנפרד.

דוגמת שימוש עם נתיבים מקומיים מאושרים:

```text
node scripts/verify-ios-push-public-config.mjs --config <ios-public-json> --android-config <android-google-services-json> --out <receipt-json>
```

מזהה החבילה נקרא מ־capacitor.config.json. זהות הפרויקט ומספרו נקראים
מתצורת Android, שחייבת לכלול את אותה חבילה. --root מאפשר לבחור עותק עבודה.
קובץ חסר, JSON לא תקין, שדות חסרים, פרויקט או מזהה חבילה שונים, או מזהה יישום
שאינו של iOS באותו פרויקט מחזירים exit 1. ארגומנטים לא מוכרים מחזירים exit 2.
הפלט מכיל רק זהות ציבורית מאומתת או קודי שגיאה; שדות נוספים ופרטי שגיאת
JSON אינם מועתקים לפלט. אין להעביר מפתחות פרטיים לקלט או לארגומנטים.

גם exit 0 מאמת רק התאמת זהות. APNs, הגדרת Firebase בחשבון, SDK,
פרופיל חתימה, בניית Native, קבלת התראה והיעד לאחר לחיצה נשארים לא מאומתים.
לפני הפעלה נדרש חיבור שמפיק אסימון FCM תקין; אסימון APNs גולמי אינו קלט
חלופי לשרת FCM הקיים. ברירת המחדל הנוכחית שמחריגה Push מ־iOS נשמרת.

בדיקות Integration מפעילות את ה־CLI עם קובצי דמה, דוחות על דיסק וקודי יציאה,
כולל דחיית פרויקט אחר ומניעת חשיפת שדות נוספים או תוכן JSON שגוי.
