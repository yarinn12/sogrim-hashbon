# מפת הקוד וסדר ההפרדה

מחלצים תחום אחד בכל סבב, עם adapter קטן ב־`src/app.mjs`. מודול תצוגה מקבל מודל מוכן ומחזיר HTML; הוא אינו קורא נתוני חשבון, מבצע בקשות או משנה מצב. שמות הפעולות, ה־CSS והמבנה הנגיש נשמרים בזמן חילוץ. שינוי התנהגות או עיצוב נעשה בסבב נפרד שניתן לבדוק.

## מה כבר הופרד

| תחום | מודול | מה נשאר באפליקציה |
|---|---|---|
| כותרת אירוע משותפת | `src/ui/eventHeader.mjs` | בחירת אירוע, משתתפים, תוויות ופעולות |
| מסך ההתראות, פריטים ומצבי טעינה | `src/ui/notificationInbox.mjs` | סינון, בחירת מצב, זמן יחסי, חשבון, ניווט, רענון ו־ACK לסימון קריאה |
| השוואת זהות מצב | `src/domain/stateIdentity.mjs` | adapters קיימים ב־`src/data/localIdentity.mjs` |
| כללי מיזוג נעיצות אישיות | `src/domain/personalEventPinMerge.mjs` | אחסון, תור שמירה ומוטציות ב־`src/data/personalEventPins.mjs` |

במסך ההתראות `backButtonHtml` ו־`noticeHtml` הם HTML שהאפליקציה יוצרת. תוכן שהגיע מהתראות נכנס לשדות טקסט ונמלט בתוך מודול התצוגה. אין להעביר תוכן משתמש דרך שדות HTML אלה. מצב המסך הוא `loading`, `error`, `account-pending`, `items` או `empty`; ה־adapter שומר את הקדימות הקיימת ביניהם.

## סדר העבודה הבא

1. חילוץ שורות אירועים וכרטיסי הבית: להכין מודל תצוגה, לשמר סדר, הצמדה, אווטרים ופעולות; לבדוק שמות ארוכים, תאריכים, טקסט מוגדל ופתיחה/תפריט.
2. חילוץ תצוגת רשימות חברים וקבוצות: להשאיר זהות, הרשאות ושמירה בשכבות הקיימות; לבדוק בקשות חברות, חסימה וקבוצות עם מעט/הרבה משתתפים.
3. חילוץ רכיבי טופס הוצאה וסיכום: רק לאחר מיפוי כל שדות העריכה, המטבעות והחישובים. בדיקות כסף, עיגול, הרשאות וסנכרון שני לקוחות הן תנאי לשילוב.
4. הפרדת תיאום הפעולות לפי תחום רק כשהגבולות של התצוגה ברורים. אין להעביר את כל `app.mjs` לשירות גדול אחר או ליצור שרת חדש כדי לשנות עיצוב.

הסדר הוא תכנית עבודה, לא הצהרה שהתחומים הבאים הושלמו. בעיות ביצועים פתוחות נבדקות במדידה נפרדת; הזזת קבצים לבדה אינה תיקון ביצועים.

## QA ומסירה לכל חילוץ

- מתעדים את המקור לפני השינוי ואת נקודת השמירה. מפרידים את המועמד ממקור הפצה שכבר נחתם.
- משווים HTML והתנהגות מול המקור הקודם. תרחישי ההתראות מקובעים ב־`tests/fixtures/notification-inbox-view.json` מ־commit `3f1976105fbc6bae48fcc1ff3ed975db5a8b98c1`; אין לעדכן טביעות מתוך המחליף רק כדי להעביר בדיקה.
- מריצים בדיקות חוזה על המודול ועל ה־adapter, את `qa:architecture` ואת `npm test`. בבדיקות קיימות שהתצוגה עברה מהן בודקים את הפלט החדש בלי להסיר את הדרישה המקורית.
- מריצים את מסעות המובייל הרלוונטיים, לרבות דפדפן WebKit, Android, טקסט מוגדל ו־reflow. בודקים שהמודול החדש מופיע במטמוני PWA ובתוצר בניית Native.
- קבלת CI וחבילות מתייחסת ל־SHA החדש. הוכחות של מקור קודם אינן עוברות אוטומטית למועמד. אין לקדם אותו לחנויות לפני תיאום המקור המשותף.
- מועמד חילוץ ששומר את מספר הגרסה הקפוא אינו מיועד לפרסום. לפני שילוב להפצה מעלים את גרסת ה־PWA בכל משטחי העדכון ובודקים שדרוג מהתקנה קיימת, כדי ש־worker חדש לא ישתמש במטמון של הגרסה הישנה.
