# לוח ניהול פרטי

## מטרה

לוח הניהול ירכז במקום אחד מידע תפעולי הדרוש לפני ואחרי ההשקה:

- מספר חשבונות רשומים ומאומתים.
- מספר מרחבי עבודה ואירועים משותפים.
- נפח הנתונים השמור במסד.
- מספר הפעלות, תקלות ושיעור הפעלות ללא שגיאה בתקופה שנבחרה.
- פילוח הפעלות לפי פלטפורמה וכשלי פעולות לפי סוג.

ה-API מחזיר נתונים מצטברים בלבד. הוא אינו מחזיר שמות, כתובות אימייל,
תוכן אירועים, הוצאות או מידע פיננסי אישי.

## אבטחה

הנתיב `GET /api/admin/overview?days=30` סגור כברירת מחדל. כדי להפעיל אותו
נדרשים כל הערכים הבאים בצד השרת בלבד:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` או `SUPABASE_SECRET_KEY`
- `ADMIN_EMAILS` כרשימה מופרדת בפסיקים של מנהלים מורשים

השרת מאמת את אסימון המשתמש מול Supabase Auth, משווה את כתובת האימייל
לרשימת המנהלים ורק אז מפעיל פונקציית SQL שמורשית ל-`service_role` בלבד.
אין להכניס את מפתח השירות לקוד הלקוח, לחבילת Android/iOS או למשתנה ציבורי.

## הפעלה מבוקרת

1. להחיל את המיגרציה `20260814143000_admin_analytics_overview.sql` בסביבת
   staging ולרוץ על קובץ האימות התואם.
2. להגדיר `ADMIN_EMAILS` ו-`SUPABASE_SERVICE_ROLE_KEY` רק בסביבת השרת.
3. להתחבר עם משתמש מנהל ולבדוק שהנתיב מחזיר נתונים מצטברים.
4. להתחבר עם משתמש רגיל ולוודא שמתקבלת תשובת `403`.
5. לעצב ולאשר מסך מנהל נפרד לפני חיבורו לניווט כלשהו.
6. להפעיל בפרודקשן רק אחרי בדיקת הרשאות נוספת.

## מה לא נכלל עדיין

מספר התקנות, הסרות התקנה ונתוני דף החנות מגיעים מ-Google Play Console
ומ-App Store Connect. הם אינם ניתנים להסקה אמינה ממספר החשבונות או
מהמדדים הפנימיים, ולכן יוצגו בלוח רק לאחר חיבור מקור רשמי מתאים.
