# העלאה לרשת

זהו מדריך להקמת סביבה נוספת. מאגר הפרויקט הפעיל הוא `yarinn12/sogrim-hashbon`; בפרסום עדכון יש להשתמש במאגר ובפרויקטי התשתית הקיימים והמורשים, ללא יצירת מאגר חלופי.

## GitHub

1. עובדים בענף מבודד של המאגר הקיים ומאמתים את ה־commit שנבחר להפצה.
2. מעלים קוד ובדיקות נדרשים, משלימים את שערי ה־QA וממזגים לפי תוכנית ההפצה.
3. לא מעלים קבצי `.env`, תיקיית `.vercel`, תיקיית `data`, או קבצי ZIP מקומיים.

## Supabase

כדי שחברים יראו את אותו אירוע ויוכלו לערוך יחד, צריך Supabase:

1. בוחרים פרויקט Supabase מזוהה ומורשה. לסביבת בדיקה חדשה יוצרים יעד נפרד מהייצור.
2. למסד חדש מחילים את `supabase/schema.sql`. במסד קיים בודקים מיגרציות חסרות, גיבוי ותאימות, ובודקים שדרוג בסביבה מבודדת לפני החלה.
3. שומרים את `SUPABASE_URL` ואת `SUPABASE_ANON_KEY`.

## Vercel

1. לפרסום עדכון בוחרים ב־Vercel את הפרויקט והצוות הקיימים המחוברים למאגר. הקמת Project חדש נדרשת רק לסביבה נוספת שנבחרה במפורש.
2. מוסיפים Environment Variables:

```text
APP_SPACE_ID=settle-friends-beta
SUPABASE_URL=the-supabase-url
SUPABASE_ANON_KEY=the-supabase-anon-key
GOOGLE_CLIENT_ID=
```

הערכים בדוגמה הם לסביבת בדיקה בלבד. התחברות Google פעילה בפרויקט, ופריסה המיועדת למשתמשים מחוברים צריכה את הגדרת הספק המתאימה. זהות מקומית אינה תחליף להרשאות חשבון ענן.

3. מפעילים Deploy.
4. אחרי הפריסה נכנסים לכתובת:

```text
https://your-vercel-domain.vercel.app/api/health
```

כשהכול תקין, הערכים של `publicUrlReady`, `cloudStorageReady`, ו-`shareLinksReady` צריכים להיות `true`.
