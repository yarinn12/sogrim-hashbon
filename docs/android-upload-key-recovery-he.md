# הקמה ושחזור של מפתח Upload ב־Android

מפתח Upload חותם את ה־AAB שמועלה ל־Google Play. כש־Play App Signing פעיל, Google מחזיקה את מפתח חתימת האפליקציה וחותמת בו את ה־APK שמסופק למשתמשים. תעודה ציבורית או fingerprint אינם מאפשרים לשחזר מפתח פרטי.

## אפליקציה עם זהות חתימה קיימת

קובצי התעודות הציבוריות הם:

- `docs/store-submission/android-upload-certificate-sha256.txt`
- `docs/store-submission/android-play-signing-certificate-sha256.txt`

ל״סוגרים חשבון״ כבר יש תיעוד בשני הקבצים. לכן היעדר חומר חתימה במחשב חדש אינו מצב הקמה של אפליקציה חדשה, ואינו מוכיח שהמפתח המקורי אבד.

`npm run native:android:key` מסרב ליצור מפתח אם אחת התעודות מתועדת וחומר החתימה החיצוני חסר. הוא גם מסרב להחליף את תעודת ה־Upload המתועדת כאשר מפתח שנמצא אינו מתאים לה. זוג חיצוני חלקי ממשיך להיחסם. אין למחוק תעודות או לשנות fingerprints כדי לעקוף את הבדיקה.

סדר השחזור:

1. במחשב הבנייה המקורי או בגיבוי הפרטי, לאתר את ה־JKS המקורי ואת `keystore.properties` התואם. אין לשלוח את המפתח או הסיסמאות בצ׳אט או להכניסם למאגר.
2. להשאיר את המפתח ואת קובץ ההגדרות מחוץ לפרויקט, בשתי תיקיות פרטיות נפרדות. אפשר להגדיר את הנתיבים באמצעות `SOGRIM_ANDROID_KEYSTORE_FILE` ו־`SOGRIM_ANDROID_SIGNING_PROPERTIES_FILE`; `storeFile` בתוך קובץ ההגדרות צריך להצביע על המפתח התואם.
3. להשוות את תעודת ה־Upload הציבורית למתועד ול־Play Console. אין להחליף אותה בתעודת App Signing; אלה תפקידים שונים.
4. לפני בחירת מספר גרסה או מסלול הפצה, להשלים את בדיקת Console המפורטת להלן. אחרי השחזור, לבנות AAB ולהשלים את בדיקות השחרור על המקור והבינארי המדויקים.

אם לא ניתן לשחזר את המפתח, יש קודם לאמת שהאפליקציה משתמשת ב־Play App Signing ושאכן מדובר במפתח Upload חסר. רק אז אפשר להכין בקשת איפוס Upload לבדיקה ואישור נפרדים. הסקריפט אינו מבצע איפוס, החלפת תעודה או פעולה ב־Play Console.

## אפליקציה חדשה ללא תעודות מתועדות

כאשר אין זהות חתימה ציבורית מתועדת ושני קובצי החתימה החיצוניים אינם קיימים, `npm run native:android:key` ממשיך לאפשר הקמה ראשונה. הוא יוצר את חומר החתימה מחוץ לפרויקט ומתעד את התעודה הציבורית. זה מיועד לאפליקציה חדשה באמת, אחרי בחירת מזהה האפליקציה שלה; העתקת פרויקט קיים אינה מבטלת את זהות החתימה שכבר תועדה בו.

## פרטים לקריאה ב־Play Console לפני עדכון

יש לקרוא את האפליקציה לפי Package `com.sogrimhashbon.app` ולשמור רק metadata ציבורי ותפעולי:

| פרט | מה לתעד |
|---|---|
| מסלולים | מצב Release וגרסאות פעילות ב־Production, Closed testing ו־Internal testing; אחוז Rollout אם הוא מדורג |
| מספר Build | `versionCode` הגבוה ביותר שכבר הועלה בכל המסלולים, כולל חבילות שאינן פעילות; העדכון הבא צריך מספר גבוה ממנו |
| Play App Signing | האם מופעל לאפליקציה הזאת |
| Upload key certificate | SHA-256 ציבורי של תעודת ה־Upload הרשומה |
| App signing key certificate | SHA-256 ציבורי של תעודת החתימה המגיעה למשתמשים; לתעד גם תעודות נוספות אם Console מציג כמה עקב שדרוג חתימה |

את התעודות קוראים במסך Play App Signing של האפליקציה. המסמך אינו מעיד על מצב Production הנוכחי, על גרסה זמינה בחנות או על צורך באיפוס.

## APK לבדיקות

`npm run native:android:apk` בונה APK של Release ודורש את מפתח ה־Upload. APK כזה אינו אוטומטית ה־APK שנחתם ומסופק על ידי Google Play. לבדיקות מקומיות קיימת תצורת Debug עם Package נפרד `com.sogrimhashbon.app.debug`, כדי לשמור על הפרדה מהתקנת החנות.

מקורות רשמיים: [חתימת אפליקציה ב־Android](https://developer.android.com/studio/publish/app-signing), [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756).
